# WikiSkill

将 Codex 原始会话整理为可复用 Wiki，再生成和改进 Skill 的本地工具。支持手动选择会话和自动监听，提供 WebUI、版本历史、反馈和独立安装。

方法来自 Google Research 的 [WikiSkill 论文](https://arxiv.org/abs/2608.27454v1)。本项目面向日常项目工作，不包含论文基准实验，也不宣称复现论文成绩。

## 快速开始

需要 Python 3.11+、[uv](https://docs.astral.sh/uv/) 和 macOS / Linux。普通使用无需 Node.js。

```bash
git clone https://github.com/Innocent-children/WikiSkill.git
cd WikiSkill
uv tool install .
wikiskill
```

命令自动初始化数据目录、启动后台并打开 WebUI。默认地址为 `http://127.0.0.1:8765`；端口占用时自动选择可用端口，以命令输出为准。

1. 在“设置”选择模型，保持默认的手动模式并保存。
2. 在知识工作台选择项目，打开“选择本机会话”，勾选会话后导入。
3. 点击“提取选定会话的 Wiki”，在执行记录查看结果。
4. 在“知识文档”选择一篇或多篇 Wiki，新建 Skill 或明确选择合并到已有 Skill。
5. 查看生成结果，再点击“安装到 Codex”；同名目标需查看差异并确认覆盖。

仅导入、浏览、搜索和保存反馈不调用模型。生成与安装是独立操作，生成或恢复历史版本不会自动修改 Codex 中的文件。

## 工作模式

| 模式 | 采集与分析 | Skill 更新 |
| --- | --- | --- |
| 手动选择会话（默认） | 用户选择导入和分析；不启动持续采集 | 选择当前 Wiki 新建或合并到已有 Skill |
| 自动监听并分析 | 持续采集；会话达到配置的等待时长、可识别轮次全部结束后，按设置间隔调度分析 | 更新关联 Skill；未关联页面生成独立专题 Skill |

### 自动采集范围

设置中的“自动扫描起始时间”默认在初始化时写入当前时间，之后保持固定。采集器按 `sessions` 和 `archived_sessions` 中 JSONL 文件的最后修改时间筛选，跳过早于起始时间的文件。

符合条件且尚未采集的会话从头读取，已采集会话继续增量读取。**老会话新增消息后，也可能连同旧正文一起进入采集范围**；此设置不是逐条消息的时间过滤。修改起始时间不会删除已有记录或取消批次。手动选择会话和显式导入历史不受此限制。

### 分析与重试

自动分析的会话等待时长从最近入库记录计算，在 WebUI 自动模式设置中填写“会话等待时长（分钟）”，默认 60 分钟，须为正整数。源文件也需满足相同的静默时长，并且所有内容已采集、可识别轮次均已结束。刚导入的历史记录也需等待；自动批次排队后出现新内容会延后执行。保存后，后台在后续配置加载时将新值用于排队和执行前检查，已开始的模型请求继续完成。手动提交、点击“执行此批”和明确重试可立即进入执行流程，无需等待静默期。

手动和自动分析均按会话内完整轮次拆批。在设置页“工作模式”填写“每批最大轮次数”，默认 1，须为正整数，两种模式共用。同一轮的待处理记录完整选入，未结束轮次继续等待；手动操作只绕过静默等待。无法归属轮次的记录随邻近轮次带入，只有此类记录的会话单独成批。原始记录完整保存，发送前不去重、不过滤，也不按大小裁剪；单轮过大仍可能被模型拒绝。

每批固定原始记录范围，新增记录留待后续批次。批次按会话内记录顺序执行，执行时读取最新 Wiki，成功后同时写入 Wiki、来源关联和已处理标记。后续批次继续补充或修正已有页面，最终 Wiki 库就是累计结果，没有额外汇总步骤。失败保留输入并暂停同一会话的后续批次，其他会话继续处理；手动执行也不能越过前序批次，重试成功后继续。此前成功批次的更新保留。

切换为手动模式会停止持续采集和后续自动调度；正在执行的模型请求继续完成，未执行的自动批次暂停。可按顺序手动执行暂停批次，或重新开启自动模式。失败不自动反复重试；“使用当前设置重新生成”会按当前轮次数限制重新划分失败批次的原始记录，各批执行时重新读取当前 Wiki。调整轮次数只影响新分批和明确重新生成，已经排队的批次保持原分组，执行中的请求继续完成。

## 模型设置

| 执行方式 | 准备与配置 |
| --- | --- |
| Codex 新建会话 | 本机可执行 `codex app-server` 并已登录；可指定模型，留空使用 Codex 默认模型 |
| API | 选择 Chat Completions 或 Gemini，填写地址、模型和服务所需的 key；服务需支持结构化输出和工具调用 |
| 本机 Ollama | 先启动 Ollama 并下载模型，再填写模型名称；使用 `http://127.0.0.1:11434/api/chat` |

Ollama 使用原生结构化输出和工具调用，设置 `think=false`、`stream=false`、temperature 0；与 API 地址和 key 独立，失败不切换其他模型。

应用不设置 token 预算、输出 token 上限或调用次数上限；模型服务自身的上下文和输出限制仍有效。执行记录展示请求/读取记录及服务实际返回的 usage，未返回的用量保持未知。报告由已有结果生成，不额外调用模型。

设置保存在数据目录的 `config.json`，建议通过 WebUI 修改。

| 配置 | 含义 / 默认值 |
| --- | --- |
| `capture_mode` | `manual` 或 `automatic`，默认 `manual` |
| `automatic_scan_since` | 含时区的 ISO 日期时间，初始化时固定；界面按本地时区展示 |
| `analysis_interval_minutes` | 自动分析调度间隔，默认 60 分钟；与会话等待时长独立 |
| `session_wait_minutes` | 会话等待时长，默认 60 分钟，须为正整数；从最近入库记录计算，并检查源文件静默 |
| `max_turns_per_batch` | 每批最大完整轮次数，默认 1，须为正整数；手动和自动共用，网页工作模式中设置 |
| `executor` | `codex`、`api` 或 `ollama`，默认 `codex` |
| `ollama_model` | 已下载的本机模型名称 |
| `api_provider` | `chat_completions`（默认）或 `gemini` |
| `api_url` / `api_model` / `api_key` | API 地址、模型与认证；默认地址 `https://api.openai.com/v1` |
| `codex_home` | 默认取 `CODEX_HOME`，未设置时为 `~/.codex` |
| `install_directory` | 默认在上述 Codex 目录的 `skills` 下 |
| `codex_command` / `model` | 默认命令 `["codex", "app-server"]`；模型默认 null |
| `timeout_seconds` / `poll_seconds` | 默认 600 秒 / 10 秒，均为正整数 |
| `auto_start` | MCP 操作是否自动唤醒后台，默认 true；不决定工作模式 |

配置只接受当前字段。配置无效时先运行 `doctor`；需要恢复默认设置时，停止后台，备份配置，再执行 `wikiskill init --reset-settings` 并重新设置模型。重置保留数据库、原文、Wiki、Skill 和报告，不自动执行模型。

## Wiki 与 Skill 管理

“原始记录”负责导入和整理会话，“知识文档”负责阅读、编辑和生成，“Skill 管理”负责查看和安装。知识历史、Skill 历史提供差异、下载与版本恢复，执行记录提供进度和重试。

Wiki 支持按名称或当前完整正文搜索，忽略大小写，中文、空格、`%` 和 `_` 按字面子串匹配。列表支持跨页选择，已用于生成的 Wiki 可再次选择；提交生成前先保存正文。生成面板默认新建，并允许搜索所有项目中 WikiSkill 管理的 Skill 后明确合并。合并保留已有资源，关联项目共同使用更新后的内容；外部目录中的 Skill 不在可修改范围内。

编辑器会提示未保存内容，切换文档或离开时确认是否放弃；刷新/关闭使用浏览器原生提示。保存失败保留输入；并发冲突时先复制需要保留的内容，再重新打开文档核对。输入仅保存在当前页面，没有自动保存或持久草稿。保存期间继续输入的内容仍需再次保存。

Skill 历史支持名称/完整路径搜索，以及管理状态、来源和项目筛选；共享 Skill 去重展示，已应用条件随 URL 保存。清空筛选保留当前项目。

Wiki 分析保留成功与失败操作的原因、适用条件和原文来源。Skill 生成读取选中 Wiki 的当前正文、可用原文及相关反馈。每次实际更新同时保存 `SKILL.md` 和包含来源、修改原因与演化记录的 `PURPOSE.md`。在历史页可针对版本填写有效、问题、不采用及备注；反馈本身不调用模型、回退或安装。恢复历史版本需填写原因，Wiki 保留。内容变化不代表实际效果已验证。

### Wiki ZIP 导入导出

在知识文档导出全部页面或跨页选中的页面。ZIP 仅包含当前 UTF-8 Markdown 正文，不包含原文、数据库、设置、历史或 Skill，因此不能作为完整知识库备份。

导入先预览，逐项确认同名修改，再确认导入；新增页无需覆盖确认，未包含的页面保持原样。预览后项目内任一 Wiki 被编辑、ZIP 改变或服务重启，都需重新预览。提交整批成功或失败，无变化页面不新增版本。网络失败时先查看当前内容，再重新预览。

ZIP 根目录只接受普通 `.md` 文件，名称匹配 `[a-z0-9][a-z0-9-]{0,100}`，正文须为非空 UTF-8；保留换行与空白。仅支持 Stored/Deflate，拒绝重复名称、目录、路径、链接、加密及损坏文件。上限为 ZIP 10 MiB、1000 页、单页 2 MiB、正文总计 20 MiB。空项目可导出空 ZIP，空 ZIP 无法导入。

## 命令与数据

| 命令 | 用途 |
| --- | --- |
| `wikiskill` | 启动或复用后台，打开 WebUI |
| `wikiskill --no-open` / `wikiskill start` | 启动后台，不打开浏览器 |
| `wikiskill status` | 查看实际地址、后台状态和内容数量 |
| `wikiskill stop` | 停止托管后台，中断运行中的模型调用，保留数据 |
| `wikiskill doctor` / `wikiskill doctor --json` | 只读环境诊断，不启动后台或调用模型 |
| `wikiskill init` | 初始化配置，输出 MCP 启动命令 |

`wikiskill-codex` 是同一 CLI 的别名。默认数据目录为 `~/.wikiskill`；自定义目录时将 `--root /absolute/data` 放在子命令前，启动、停止及 MCP 使用相同目录。关闭浏览器或终端后托管后台继续运行；手动模式运行页面和 worker，自动模式另有 collector。独立启动的 worker/collector 需在其终端停止。

原文以字节保存，展示中的编码替代字符不会修改原始字节。未知事件也保留，但无法恢复 Codex 未记录、加密或截断的内容；WikiSkill 自身转换会话排除采集。原文、生成内容和模型响应可能包含会话中的敏感信息，分享前检查内容。HTTP 仅接受本机 Host，浏览器访问要求同源。

### MCP 接入

执行 `wikiskill init`，将输出的 `mcp_command` 数组注册为本机 stdio MCP：首项为可执行程序，其余项为参数。连接后按 `auto_start` 设置唤醒后台，不打开浏览器；自动采集独立于 MCP 连接。

| 工具 | 用途 |
| --- | --- |
| `wikiskill_context` | 读取项目生成的 Skill |
| `wikiskill_query` / `wikiskill_status` | 查询 Raw、Wiki、报告和运行情况 |
| `wikiskill_wiki` | 以项目绝对路径和 name/body 页面数组写入 Wiki |
| `wikiskill_history` / `wikiskill_rollback` / `wikiskill_retry` | 查询历史、恢复和重试 |

可用 `wikiskill install-skill` 安装辅助说明，用于查询和用户要求的 Wiki 写入；采集不需要模型主动提交 Raw，也不需要调用该 Skill。

## 排查问题

- **后台未启动**：运行 `wikiskill status` 和 `wikiskill doctor`，查看数据目录下的 `service.log`、`worker.log`。停止后又被 MCP 唤醒时，关闭 `auto_start`。
- **自动分析没有开始**：确认自动模式、扫描起始时间、会话是否结束及是否达到设置的会话等待时长；检查是否已有等待或失败批次。
- **模型生成失败**：展开执行记录的“模型响应原文与工具调用”，查看正文、思考字段、工具参数和结束原因。修正设置后选择“使用当前设置重新生成”。未收到响应的网络失败可能没有响应文件。
- **安装冲突或失败**：重新查看来源和目标差异，再确认安装。安装保留恢复记录，下次安装会尝试恢复已授权的复制。

`doctor` 检查本地配置、路径权限及执行方式所需字段；不会连接 Codex、API 或 Ollama，也不验证登录、模型可用性或数据库内容完整性。JSON 返回 `ok`、`executor`（`codex` / `api` / `ollama` / null）和 `checks`；检查项包含 `id`、`status`、`message`、`repair`。存在 error 时退出 1，只有 ok/warning 时退出 0。初始化前也可运行，修复建议需自行执行。

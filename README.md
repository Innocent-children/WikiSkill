# WikiSkill

将 Codex 原始会话整理为可复用 Wiki，再生成和改进 Skill 的本地工具。基于 Google Research 的 [WikiSkill 论文](https://arxiv.org/html/2608.27454v1)的方法，面向日常项目工作；不包含论文基准实验、评分、消融或跨模型评测。

Python 3.11+，macOS / Linux。前端开发需要 Node.js 22.12+。

```bash
uv tool install .
wikiskill
```

从源码运行：`uv sync --frozen` 后执行 `uv run --frozen wikiskill`。安装包包含 WebUI，普通使用无需 Node.js。默认页面地址 `http://127.0.0.1:8765`；端口占用时自动选择可用端口。

## 两种工作模式

在 WebUI 设置中选择模式和模型，保存后生效，默认使用手动模式。

| 模式 | 原始记录 | Wiki | Skill |
| --- | --- | --- | --- |
| 手动选择会话 | 打开“选择本机会话”，勾选后导入；不启动持续采集 | 点击“提取选定会话的 Wiki”，或从已导入记录中选择分析 | 选择一篇或多篇当前 Wiki，新建或合并到已有 Skill |
| 自动监听并分析 | 后台持续保存新增轨迹 | 首次有待处理内容时分析，之后按设置的分钟间隔处理新增已结束轮次 | Wiki 更新后自动更新关联 Skill；尚未关联的页面生成独立专题 Skill |

浏览、搜索、导入和保存反馈不调用模型。手动模式只分析用户提交的记录。两种模式的生成结果均先保存在 WikiSkill；“安装到 Codex”沿用独立的差异确认与完整目录复制。

自动模式首次采集从启用时开始；需要更早的会话时，可手动选择导入。已处理原文不会反复分析。自动分析按 Codex 会话创建独立批次，每批包含该会话全部待处理的已结束轮次，原文保持完整。手动整理和多会话导入分析也按会话拆批。批次顺序执行，并在执行时读取最新 Wiki；失败只暂停对应会话，其他会话继续整理。

切换到手动模式会停止持续采集和后续自动调度；正在分析的批次会完成并保存结果，尚未开始的自动批次暂停，可在执行记录点击“执行此批”或重新开启自动模式。失败批次保留输入并停止自动重试，避免重复消耗。

## 模型与用量

- **Codex 新建会话**：使用本机 Codex 登录和指定模型。
- **API 模型**：配置 Chat Completions 或 Gemini 地址、模型与 key。
- **本机 Ollama**：先运行 Ollama 并下载模型，在设置中填写模型名称。使用原生 `http://127.0.0.1:11434/api/chat` 接口，显式设置 `think=false`、`stream=false` 和 temperature 0，独立于云端 API 地址和 key，失败不切换其他模型。

Wiki Maintainer 使用论文附录 E.2 原始提示词，接收选定原文和当前 Wiki，通过 JSON Schema 约束返回模式创建、补丁、完整目录和日志。Skill Proposer 使用附录 E.3 原始提示词，通过真实 read_file 工具读取本批材料，调用 finish 提交 create、patch 或 no_action。项目适配要求与原始提示词分开记录。手动和自动模式都不设置应用级 token 预算、输出 token 上限或调用次数上限；轨迹按会话拆批，同一会话原文不会按大小裁剪或继续拆分，也允许重复读取所需材料。模型服务自身的上下文与输出限制仍然有效。

执行记录保留请求次数、读取记录以及 API/Ollama 实际返回的 usage，未返回的用量保持未知。展开“模型响应原文与工具调用”可查看每次尝试收到的原始响应，包含正文、思考字段、工具参数和结束原因；解析失败也会保留响应。失败沿用原逻辑：保留输入和失败记录，不自动反复重试。报告由已有结果生成，不额外调用模型。

## 知识如何改进

Wiki 分析对比成功与失败操作，记录根因、适用条件、实际验证和未知结果，合并或修正已有模式；更新已有页面前须完整查阅该页，并以精确补丁修正内容，避免整篇重写丢掉无关知识。模式目录和演化日志单独保存，不参与专题 Skill 生成。每篇生成页面记录本批原文来源，人工编辑和版本历史保留关联，可在页面查看原始记录。

Skill 生成使用选中 Wiki 的**当前正文**，避免把过时版本并列作为有效指导。存在关联原文时，生成器需要查阅原文；目标 Skill 有负面反馈时，需要查阅最近反馈对应的历史修改，其他历史按需查阅。已有 Skill 支持精确补丁修改。每个实际更新同时保存 `SKILL.md` 和包含来源版本、修改原因与演化记录的 `PURPOSE.md`，其他资源保持原样。

在 Skill 历史页可填写实际有效、遇到问题、不采用和补充说明。反馈针对选定版本，后续生成会参考它；反馈本身不会调用模型、回退或安装文件。恢复历史版本时填写原因，Wiki 保留。来源页面更新后，界面提示可重新选择合并；自动模式会更新其关联 Skill。

这些机制帮助改进知识质量，但内容变化不等于效果经过验证；项目不宣称复现论文成绩。

## 运行与数据

| 命令 | 用途 |
| --- | --- |
| `wikiskill` | 启动或复用后台，打开 WebUI |
| `wikiskill --no-open` / `wikiskill start` | 启动后台，不打开浏览器 |
| `wikiskill status` | 查看地址、后台和内容数量 |
| `wikiskill stop` | 停止后台，保留数据 |
| `wikiskill doctor` | 只读环境诊断，不调用模型 |

默认数据目录为 `~/.wikiskill`；指定目录时将 `--root /absolute/data` 放在子命令前，启动和停止使用相同目录。关闭浏览器或终端后托管后台继续运行。手动模式后台只有页面与 worker，自动模式另有 collector。

原文以字节保存，偏移与写入同事务提交；未知事件也保留。只能保存 Codex 实际写出的内容，不能恢复加密、未记录或已截断的输出。转换会话排除采集。Wiki 编辑有并发检查，Skill 有完整快照和发布恢复，安装支持同名差异确认。Wiki ZIP 导入导出只传递当前 Markdown 正文。

**从旧配置升级**：停止旧后台，执行 `wikiskill init --reset-settings`，再在设置页选择模式与模型。配置只接受当前格式；旧的阈值、自动开关、token 预算和调用次数限制字段已移除，不做兼容识别。重置设置保留数据库、原文、Wiki、Skill 和报告，不自动运行模型。

需要 MCP 时，运行 `wikiskill init`，按输出注册本机 stdio MCP。MCP 与 WebUI 使用同一数据目录。详见 [Codex 接入](docs/codex-integration.md)、[WebUI 与开发](docs/webui.md) 和 [演化流程](docs/evolution.md)。

## Ollama 实测与开发检查

已用本机 `qwen3.5:9b` 实测 Wiki 创建、Wiki 补丁、Skill 创建、结合反馈修改 Skill，以及无可复用知识时的 `no_action`。这些是合成轨迹上的真实模型集成检查，不是论文成绩复现。

可显式运行隔离实测（会调用本机模型，保留临时数据和响应，不修改现有知识库或安装 Skill）：

```bash
uv run python scripts/verify_ollama_workflow.py --model qwen3.5:9b
```

原始提示词、许可与适配说明见 [prompts/ADAPTATIONS.md](wikiskill/live/prompts/ADAPTATIONS.md)。

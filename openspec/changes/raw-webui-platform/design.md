## Context

`Store` 管理 SQLite 事务和查询，`Runtime` 管理批次调度及消费，`SkillManager` 管理目录快照和发布恢复，`CodexSession` 管理 app-server 连接。`ReadView` 与 FastAPI 为 React 页面提供只读数据。沿用这些职责，将采集、安装、API 执行分别放入明确的业务模块。

## Goals / Non-Goals

完成规格里的采集、转换、管理和安装整条流程，现有数据保留。仅操作本仓库，不增加外部 Skill 纳管、多项目共享、远程部署、论文实验或旧配置兼容。

## Decisions

### 原文与解析分开

新增轨迹来源、原文记录和轮次索引表。来源记录文件身份、分段、读取位置与会话元数据，原文记录以 BLOB 保存每行字节与偏移；唯一来源段和偏移防重复。轮次索引仅负责项目、会话、轮次、完成状态及转换消费关系。解析失败也保存原文，页面可看原文和解析状态。

首次扫描登记已有文件末尾作为开始位置，后续只读新增完整行。用户主动导入历史时读取这些文件的早期部分，用相同来源偏移去重。归档文件按身份和会话识别；文件截断或替换新建段，原记录保持。初次启用时会话元数据可只读解析用于归属，不将启用前正文偷偷导入。

新增采集模块在后台独立执行循环，与转换 worker 共用 SQLite，分别持有进程锁。MCP 启动唤起后台，关闭页面不会停止工作。转换 Codex 会话使用 WikiSkill 数据目录作为 cwd，并在开始后登记线程 ID；采集端同时检查 cwd 与登记信息，避免线程 ID 登记前的短暂窗口回流。

### 固定批次与输入预算

Raw 批次选定待处理轮次或未归属记录，入队事务内固定记录 ID；手动和阈值调度调用同一入口。后续追加记录不进入旧批次。转换上下文在首次执行时保存，重试默认沿用；显式重新生成才更新上下文。失败批次继续占用相应阶段，用户从执行记录重试，避免自动重试风暴。

原文字节始终完整保留。模型输入按配置文本预算分批，不以截断后的摘要替换 Raw；单条超出预算应明确失败并保留未处理状态。自动阈值使用结束轮次，未知事件和未完成轮次可在页面手动处理。Wiki 阈值按正文变更版本计数。

### 执行设置与结果处理

配置采用唯一新格式：采集路径、两阶段自动开关与阈值、API/Codex 执行方式、API 协议/地址/模型/密钥、Codex 命令/模型、超时与安装目录。设置存储限制本机读取权限，读取 API 只给密钥是否已配置；空输入保留密钥，单独操作清除。配置类只验证数据，保存与界面请求由业务层完成。

抽取两种执行方式共用的提示词和输出结构。API 执行适配现有 Chat Completions/Gemini 客户端，保持与 `CodexSession` 相同的生成接口；批次保留所选执行方式和非密钥配置，密钥执行时从当前配置读取。API 模式直接生成本地报告；Codex 模式保留独立会话及报告关联。持久化结果和发布仍由 Runtime/SkillManager 负责。

### Wiki 版本与恢复

MCP 和 WebUI 共用 Wiki 写入逻辑；WebUI 提交所读取的正文 digest，事务内比较后保存。Wiki 版本需要保留真实的 A→B→A 修改，去除现有按正文 digest 永久去重对回退的影响，已有历史行保留。回退作为新正文版本。Raw 生成仍检查其读取时的页面内容，拒绝覆盖并发修改。

Skill 保留现有 prepared/applied 发布记录、锁和 before/after 快照。回退先恢复未完成发布，再创建新发布记录。WebUI 接入已有差异、报告、重试与版本查询。

### 安装职责

新增安装业务负责数据目录 Skill 到 Codex skills 目录的完整复制。预览返回来源与目标 digest、差异和目标是否存在。安装持有相应锁，重新核对来源与目标 digest，同名目标需要明确确认；目标符号链接与越界路径拒绝写入。先准备完整临时目录，保留旧目录并原子替换；保留安装日志和快照供失败恢复。生成或回退数据目录不自动安装。

### WebUI 与删除范围

复用当前导航、Markdown、分页和 SSE，增加 Raw 会话/轮次与旧摘要区别、批次选择、Wiki 编辑、设置及安装确认。HTTP 写接口由 FastAPI 同源/本机中间件保护，JSON 请求校验输入；失败返回可展示错误，耗时转换只入队。

删除实验 CLI、benchmarks、environments、演化评分候选及其专属提示词/示例/文档/测试和可选依赖。先检查 imports，保留模型、JSON 工具等业务仍用的模块；README、安装命令和包描述改为日常产品。外部纳管旧记录保留，主流程仅自产 Skill。

## Risks / Trade-offs

- Codex JSONL 不是稳定接口：独立解析适配器，未知记录原样存储并显示解析状态；不推测不可取得内容。
- 原始轨迹可能很大：增量读取、分页和输入预算限制执行负载；不静默裁剪存储。
- 本地进程可访问本地密钥：文件权限和接口遮蔽防止意外展示，不引入远程账户体系。
- 双循环共用 SQLite：事务短小，模型执行和文件读取在事务之外；提交位置与原文同事务。
- 旧配置不兼容：明确提示按当前格式重新配置；数据库内容保留，不自动清空。
- 模型效果依赖实际服务：使用隔离数据验证协议和工作流；真实服务未运行时在交付里说明。

## Migration Plan

仅新增原文相关表并调整 Wiki 正文历史的去重约束，旧摘要与发布历史保留；初始化前后的测试数据用于确认。停止旧后台后重新启动新版本，按新设置页配置。应用升级不写 Codex 源文件或已有目标 Skill，安装由用户操作触发。

## Open Questions

没有阻塞实现的用户决策。历史导入、旧摘要保留与同名覆盖已由用户明确确认；轮次计量和初始自动开关作为当前设计选择记录。

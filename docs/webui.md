# WikiSkill 本地 WebUI

WebUI 展示 Codex 业务接入中的项目经验、Wiki、后台批次和 Skill 发布记录。界面使用浅灰背景、白色内容区和蓝色强调，随系统切换明暗外观。首页直接展示项目积累和当前处理状态。

## 启动

```bash
uv sync --frozen
uv run --frozen wikiskill-codex web
```

打开 `http://127.0.0.1:8765/`。安装好的 Python 包中包含前端资源，运行 WebUI 无需 Node.js。

指定已有数据目录或端口：

```bash
wikiskill-codex --root /absolute/path/to/wikiskill-data web --port 8766
```

`--root` 放在 `web` 前。监听地址只接受 `127.0.0.1`、`localhost` 或 `::1`，默认 `127.0.0.1`。Web 服务、MCP 和 worker 分别运行；关闭网页或 Web 服务会结束查看连接。

页面通过只读 SQLite 连接读取已有记录。打开页面和查询详情不会创建项目、初始化数据目录、唤起 worker、调用模型或改变消费记录。数据目录尚未初始化时，页面显示使用说明；已有空数据库显示等待采集。

## 页面

| 页面 | 可以查看的内容 |
| --- | --- |
| 运行总览 | 项目选择、待整理经验、待处理批次、关联 Skill、当前批次及各层积累情况 |
| 优化批次 | 按项目、阶段和执行状态筛选，分页查看批次、时间线、固定输入、结果及报告 |
| Raw 与 Wiki | 原始提交和元数据、去重关系、关联批次、当前 Wiki 正文及各 Skill 的消费情况 |
| Skill 历史 | 当前磁盘正文、已发布正文、版本差异、修改前后正文、完整目录文件清单和快照文件下载 |
| 运行信息 | worker 心跳、进程、当前批次、模型和阈值配置、数据及日志目录 |

项目身份沿用业务入口规则：同一 Git common-dir 的 worktree 合并展示。多个项目共用一个 Skill 时，版本记录共享，Wiki 待处理数量按项目和 Skill 分别统计。关闭外部 Skill 管理后，页面仍可查看已经保存的历史。

Raw 中的 `problem`、`action`、`outcome`、`lesson` 保留原始提交形式；不同提交里的相同观察关联到同一条去重记录。重复内容参与原始提交展示，新增计数只计算第一次保存的不同观察。

Wiki 的正文版本可以查看产生它的批次及该批次输入。手动写入的正文显示为手动提交。Skill 版本中的目录、空目录、权限和文件大小来自保存的完整快照，下载接口仅提供选中快照内的文件。

## 状态怎样理解

Raw 阈值按项目中未消费的不同观察条目计量，Wiki 阈值按对应 Skill 未消费的不同正文版本计量。页面把未消费数量拆成“本批输入”和“后续积累”；同一批次执行期间，新内容留给后续批次。

达到阈值不代表已经开始生成。页面显示等待调度、已入队、失败批次待重试、共享 Skill 被其他批次占用、管理关闭或配置读取失败等具体原因。失败批次及其输入继续按现有 worker 规则保留。

批次展示三项独立信息：

- **执行阶段**：准备输入、连接 Codex、生成内容、保存结果、写入内容及发送报告。
- **内容结果**：尚未写入、Wiki 已更新、Skill 已发布、无新增版本或发布待确认。
- **会话报告**：尚未发送、正在发送、发送待确认、已发送或发送失败。发送阶段缺少有效 worker 心跳时显示发送待确认。

`no_change` 表示批次成功处理并消费输入，没有新增内容版本。报告发送失败时，已经发布的 Skill 仍显示已发布。存在保留的发布记录但尚未确认应用时，页面显示发布待确认。即使批次执行失败，也单独展示实际版本发布记录。

失败批次重新入队后，本次报告显示尚未生成，上一次尝试的报告单独展开。时间线保留重试和失败事件。模型生成耗时按实际记录显示，页面不推算完成百分比。旧批次没有记录的开始、结束和阶段时间显示为未记录。

## 实时更新

业务写入在 `runtime_events` 保存事件序号、关联项目或批次、事件类型、时间和必要详情。关键状态修改与对应事件处于同一个事务。worker 的进程信息和心跳存放在 `worker_runtime`，心跳由独立线程每 5 秒更新，等待模型响应期间也持续运行。

Web 服务使用独立的只读 SQLite 连接，约每秒检查一次其他连接的提交及配置文件变化，通过 SSE 通知浏览器重新读取当前页面数据。心跳过期也会产生页面更新，即使此时数据库没有新的提交。一般在提交后 1～2 秒内看到变化，具体还取决于本机负载。

页面首次打开和 SSE 重新连接后会读取完整快照。SSE 的事件 ID 对应已保存的事件序号；重新连接用当前快照恢复状态，历史事件通过批次时间线分页读取。Web 服务重启、页面刷新和断线不会重新执行优化。

15 秒没有新的心跳时，worker 显示心跳过期，生成中的批次显示状态待确认。页面连接断开与 worker 心跳过期分别显示。断线时保留最后成功读取的数据及时间；历史版本的 worker 没有心跳记录时显示未记录。升级后需由正常的 worker 启动流程加载新代码。

实时信息覆盖 WikiSkill 收到的显式经验提交和自身后台优化过程；普通 Codex 业务任务的完整工具调用与对话没有被自动采集。

## 本地读取接口

所有接口均为 GET，请求通过已登记的项目、批次或 Skill ID 选取内容。

| 路径 | 返回内容 |
| --- | --- |
| `/api/snapshot` | 配置、worker、项目积累和总体数量 |
| `/api/events` | SSE 更新通知 |
| `/api/jobs` | 批次列表，支持 project、state、stage、offset、limit |
| `/api/jobs/{id}` | 批次详情、当前及上次报告、已保存的模型输出 |
| `/api/jobs/{id}/inputs`、`/events`、`/report` | 批次输入、时间线、报告下载 |
| `/api/projects/{id}/raw`、`/raw/{raw_id}` | 原始提交列表和详情 |
| `/api/projects/{id}/wiki`、`/wiki/{name}` | Wiki 列表、正文、历史变化和消费情况 |
| `/api/skills/{id}` | Skill 详情和分页版本历史 |
| `/api/skills/{id}/versions/{version_id}` | 差异、前后正文和目录清单 |
| `/api/skills/{id}/versions/{version_id}/file` | 通过 side 和 name 下载快照内的文件 |

列表分页使用 `offset >= 0`、`1 <= limit <= 100`，默认页面每页 20 条。未知记录返回 404，错误查询参数返回 422，暂时无法读取数据库时返回 503。

服务只接受本机 Host，数据接口拒绝跨站 Origin。Markdown 支持代码块和表格，原始 HTML 和远程图片保持为非执行内容；文件下载使用附件响应。页面中的业务操作由现有 CLI/MCP 入口负责，Web 接口负责只读展示。

## 开发与验证

前端源码位于 `web/src`，按共享组件和五个页面分开。Python 的 `views.py` 负责只读查询和页面数据，`web.py` 负责 HTTP/SSE，`telemetry.py` 负责独立心跳，业务阶段事件由 runtime 和 Skill 发布流程记录。

前端开发使用 Node.js 22.12+；本次开发环境为 Node.js 24。启动 Python Web 服务后，在另一个终端运行：

```bash
cd web
npm ci
npm run dev
```

开发服务器将 `/api` 转发到 `127.0.0.1:8765`。完成前端修改后执行 `npm run build`，产物写入 `wikiskill/live/web_assets` 并随 Python 包分发。`uv build` 会把前端源码加入源码包、把构建产物加入安装包；发布 Python 包之前应先完成前端构建。

```bash
uv run --frozen python -m unittest discover -s tests -p 'test_live_*.py' -v
cd web
npm test
npm run build
```

测试使用隔离目录和固定模型响应，覆盖既有 Codex 接入流程、新增查询与计数、发布与报告分离、独立心跳、真实本地 HTTP/SSE 连接、重连、只读访问及前端响应乱序处理。它们验证程序行为，不消耗真实 Codex 模型调用。

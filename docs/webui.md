# WebUI 与开发

知识工作台按“原始记录 → 知识文档 → Skill 管理”组织操作，先选择项目再操作。原始记录负责选择对话和整理 Wiki；知识文档负责阅读、编辑、选择 Wiki 并生成 Skill；Skill 管理负责查看结果和安装。知识历史、Skill 历史负责差异、资源下载和版本恢复。执行记录负责进度、固定输入、报告和失败重试。设置负责模型、自动整理、历史导入和后台启动，工作台使用指南只提供相关页面链接。

Wiki 列表支持单选、多选、选择本页、跨页保留选择和清空选择；正文详情支持从当前 Wiki 生成。未保存的正文需要先保存。生成面板默认新建并建议一个可用名称，同时搜索 WikiSkill 管理的所有项目 Skill，按名称与正文的共同词排序，支持按名称、用途、正文和关联项目过滤。共同词只是查找线索，用户阅读目标正文后选择合并；合并更新原 Skill 并保留其资源，关联项目共同使用更新后的内容。外部目录中的 Skill 不在可修改范围内。

知识工作台的“知识文档”和知识历史的“知识页面 Wiki”均支持搜索。在“搜索 Wiki”中输入名称或正文内容，按 Enter 或点击“搜索”；点击“清空搜索”恢复全部文档。搜索仅匹配当前项目的名称或完整的当前正文，不区分大小写；中文、空格、`%`、`_` 等按字面子串匹配。结果保持原来的名称顺序，修改或清空条件回到第一页，翻页保留条件，没有匹配时会显示提示。工作台已打开的文档和已选 Wiki 保持不变；知识历史的搜索条件保存在页面 URL 中。搜索不查询历史正文，也不修改正文或新增版本。

读取接口 `GET /api/projects/{project}/wiki` 接受可选的 `q` 参数，与 `offset`、`limit` 配合使用。先过滤再分页；省略 `q` 或传空字符串与原列表一致。例如 `?q=100%25&limit=20&offset=0` 搜索字面的 `100%`。调用时使用 URL 查询参数编码。

手动生成使用所选 Wiki 的当前完整正文，已经用于生成的 Wiki 仍可再次选择。预览与提交之间正文或目标 Skill 发生变化会提示重新读取。提交时固定所选正文及目标内容，超出模型输入上限时整批拒绝并给出提示。新建与合并均沿用生成记录、失败重试和版本发布流程，生成后从结果进入正文或安装页面。

自动 Raw→Wiki 继续按已结束轮次计数；自动 Wiki→Skill 按新增正文版本计数，只更新该项目的汇总 Skill。专题 Skill 和从其他项目关联的 Skill 由用户在 Wiki 页面选择内容后更新。手动生成不受自动阈值限制。

设置按执行方式展示 Codex 或 API 配置，开启自动整理后才显示对应阈值；目录、超时和启动命令收在高级设置中。后台信息和本地文件位置单独折叠。

HTTP 仅接受本机 Host，浏览器访问要求同源。JSON 写操作返回输入错误或冲突提示；模型任务入队后由后台执行。GET 原文提供原始字节 base64 和单独的展示文本，未知编码的展示替代字符不会修改保存的字节。

## Wiki ZIP 导入导出

在知识工作台选择项目并进入“知识文档”。“导出全部 Wiki”下载全部已保存页面，不受分页影响；“导出选定 Wiki”复用列表的跨页选择，未选中时禁用。ZIP 只包含对应页面的当前 UTF-8 Markdown 正文，文件名为 `<页面名>.md`，不附带原始会话、设置、密钥文件、数据库、历史或 Skill。正文内用户已经写入的内容按原样保留。

导入时选择 ZIP，点击“预览 / 重新预览 ZIP”。预览只读数据库，分别显示新增、修改和无变化页面；同名修改展示差异和完整前后正文，须逐项勾选确认，随后点击“确认并导入”。文件改变或导入失败后旧预览与确认失效，需要重新预览。未出现在 ZIP 中的页面保持原样。

服务端在同一个事务内复核整个项目的完整正文 digest 与 Wiki 编辑序号，再调用已有 Wiki 写入、历史和事件逻辑。预览后任一 Wiki 被编辑（包括空白变化或改回旧正文），或换用另一个 ZIP、项目、重启服务，均会整批拒绝。新增与修改各记录一个版本，包括仅空白不同的导入；无变化页面不写入、不改元数据、不增版本。校验失败或事务中途出错不会留下部分页面或版本。

ZIP 规则：根目录只放普通 `.md` 文件；页面名称匹配 `[a-z0-9][a-z0-9-]{0,100}`。正文为非空 UTF-8，保留原换行与空白。拒绝重复名称、目录、路径、链接、加密、非 Markdown 文件及损坏的 ZIP；只支持 Stored/Deflate。ZIP 最大 10 MiB，最多 1000 页，单页最大 2 MiB，正文总量最大 20 MiB，超限整批报错。空项目可以导出空 ZIP，空 ZIP 导入会提示没有页面。

接口沿用本机 Host 和浏览器同源限制：

| 方法与路径 | 请求／响应 |
| --- | --- |
| `GET /api/projects/{project}/wiki-export` | 下载全部 Wiki，`application/zip` |
| `POST /api/projects/{project}/wiki-export` | `{"pages":["build","tests"]}`，只读下载选定 Wiki；空列表、重复或缺失页面报错 |
| `POST /api/projects/{project}/wiki-import/preview` | `{"archive_base64":"..."}`；返回 `pages`（状态、前后正文、diff、expected_digest）、`counts` 和 `preview_token` |
| `POST /api/projects/{project}/wiki-import` | `{"archive_base64":"...","preview_token":"...","overwrite":["build"]}`；确认列表必须精确包含所有修改页，新增页无需加入；返回 `new_changes` 和 `counts` |

输入与冲突错误返回 `409` 和 `detail`，项目不存在返回 `404`。提交须使用同一次预览的原 ZIP 与 token。前端收到失败后要求重新预览；网络失败时可先在知识文档确认当前内容，再重新预览。

## Wiki 未保存内容

修改 Wiki 正文，或填写新建 Wiki 的名称、正文后，页面显示“有未保存的修改”。切换文档、再次新建、切换项目或页面，以及浏览器前进/后退时，会先确认是否放弃修改。取消会保留当前名称和正文；重复打开当前文档、选择列表条目用于生成 Skill 或翻页不会丢弃编辑内容。

刷新或关闭标签页使用浏览器原生离开提示，文字和展示条件由浏览器决定。没有改动、把输入改回已保存内容，或保存成功后可以正常离开；保存期间继续输入的内容仍需再次保存。实时状态刷新保留当前编辑内容。

保存失败时输入会保留，离开提示继续有效。若提示正文发生冲突，请先复制需要保留的内容，再确认离开并重新打开文档核对；应用沿用正文摘要检查，防止覆盖其他已保存内容。写入成功但读回失败时也会保留输入并提示错误。内容仅保留在当前打开的页面中，确认放弃后不保留草稿；没有自动保存或浏览器持久草稿。

## Skill 历史搜索与筛选

在“Skill 历史”输入名称或完整路径中的任意一段，按 Enter 或点击“搜索”应用。搜索忽略大小写与首尾空格；管理状态可选全部、开启、关闭、配置待确认，来源可选全部、WikiSkill 生成、外部。下拉选择立即生效，与已应用的搜索和顶部项目选择共同筛选。

同一个 Skill 关联多个项目时只显示一次。列表显示匹配数量和当前项目范围内的去重总数；“尚无 Skill”表示该范围还没有关联 Skill，“没有匹配结果”表示已有 Skill 但不符合当前条件。

已应用条件保存于 URL，例如 `#/skills?project=alpha&q=build&status=enabled&source=owned`。刷新、浏览器前进后退可恢复条件和结果；切换项目、打开详情、切换版本和返回“全部 Skill”会保留列表条件。“清空筛选”清除搜索、管理状态和来源，保留顶部项目选择。未提交的搜索文本属于输入草稿；未知的状态或来源参数按“全部”处理。

定向检查：在 `web` 目录执行 `npm test -- src/pages/Skills.test.tsx`，覆盖组合筛选、去重、空态、URL 恢复和详情操作。随后执行 `npm run build`，通过 WebUI 实际查看构建结果。

## 开发

```bash
uv sync --frozen
uv run python -m unittest discover -s tests
cd web
npm ci
npm test
npm run build
```

前端使用 React、TypeScript、Vite；需要 Node.js 22.12+。构建资源写入 `wikiskill/live/web_assets`，Python 包直接提供这些资源。Python 测试使用临时目录、模拟 JSONL 和本地协议桩，避免写入正式数据。

后端职责：`capture.py` 读取轨迹；`Store` 管理事务与查询；`Runtime` 调度和转换；`SkillGeneration` 负责当前 Wiki 选择、合并候选、新建和合并入队；`models.py` 适配 API；`CodexSession` 管理 app-server；`SkillManager` 发布恢复；`Installer` 复制到 Codex；`ReadView`/`TraceView` 生成读取数据；`web.py` 提供同源 HTTP 操作。

OpenSpec 变更位于 `openspec/changes/raw-webui-platform`。代码和规格描述同一个完整流程，实验内容不再包含于发行包。

API 设置可填写最大输出和上下文窗口，单位为 tokens，默认分别为 384000 和 1000000。最大输出传入模型请求；上下文窗口记录模型容量。输入完整提交，超限由模型服务返回错误，应用不按字符数分批或拒绝输入。额度只校验正整数，不设固定上限。
